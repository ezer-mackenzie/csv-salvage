# Security Policy

## Supported Versions

We take the security of `csv-salvage` seriously. The following table indicates which versions currently receive security updates:

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |
| < 0.1.0 | :x:                |

## Reporting a Vulnerability

If you discover a potential security vulnerability in `csv-salvage`, please report it responsibly rather than opening a public issue.

### How to Report

1. **Email Privately**: Send details of the vulnerability to [ramirez.ruiz.eliezer.reuven@gmail.com](mailto:ramirez.ruiz.eliezer.reuven@gmail.com).
2. **GitHub Security Advisories**: If available, you may also report vulnerabilities using GitHub's private vulnerability reporting feature in the repository's **Security** tab.

### What to Include in Your Report

To help us triage and resolve the issue quickly, please include:
- A clear description of the vulnerability and its potential impact.
- Step-by-step reproduction steps or a minimal proof-of-concept (e.g., a specially crafted malformed CSV file causing unexpected behavior or memory issues).
- Affected versions, OS, Python version, and Rust architecture.
- Any suggested mitigations or patches if you have one.

### Response Timeline

- **Initial Response**: We will acknowledge receipt of your report within 48 hours.
- **Triage & Fix**: We will work on a fix and validate it with you before publication.
- **Disclosure**: Once a patch is released, we will publicly credit the reporter (unless you prefer to remain anonymous).
